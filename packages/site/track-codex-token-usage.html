How do I see how many tokens I use in Codex?

Codex saves a usage log on your computer for every session, in ~/.codex/sessions, with token counts per turn and the model used. Caldera, a free, open-source Obsidian plugin, reads those logs on the computer where you run Obsidian and charts your Codex tokens per day and by model on your profile. It publishes counts only, never prompts, file names or costs.

Updated 2026-11-24 · by mjonesone, LLC

Log paths and fields as described in the Caldera guide, checked November 24, 2026. Codex can change its log format; if the AI usage section is empty, check that ~/.codex/sessions exists on that computer.

Where does Codex keep its usage logs?

Codex writes one JSONL file per session under ~/.codex/sessions/. Each turn adds a token_count event with that turn's usage, and the model is recorded in turn_context. Because the logs are local files, you can total them without API access. Claude Code keeps similar logs in ~/.claude/projects/, so both can sit on one chart.

How do I chart my Codex tokens with Caldera?

  1. Install Obsidian (free at obsidian.md) on the computer where you run Codex.
  2. Install Caldera from Obsidian's community plugins, or paste the setup prompt from caldera.social/#install into Codex itself and let it install the plugin.
  3. Type your name and a handle in the Welcome window. Your page goes live at caldera.social/@yourhandle.
  4. The AI usage section fills in by itself on that computer: total tokens, a daily chart, and shares by model and provider. You choose which sections show in Caldera/profile.md, so you can hide it any time.

A GitHub sign-up alone gives you a page and a city, but token usage from local logs needs the Obsidian plugin.

Can I add other computers or tools?

Yes. The plugin reads logs only on the computer it runs on. For a second machine, or for your own products' API usage, have your AI agent write an ai block (counts by model and provider) into Caldera/activity.json in your vault on a schedule. Any tool that keeps local usage logs can be added the same way. The prompt for this is in the Caldera guide, and using Claude Code, Codex or Cursor with Obsidian covers the daily routine.

Why are my totals so large?

Agent sessions re-read cached context again and again, so totals are often mostly cache reads. Charting by model shows how much each model actually works for you. For the same view across tools, see track AI token usage by day and by model.

What does this not cover?

Caldera charts usage from local logs. It does not read your OpenAI account, plan limits, billing or sign-in tokens; check OpenAI's own documentation for those. The live agent drones on your GitHub city work through Claude Code hooks, not Codex, as of November 2026 (see track your Claude Code activity).

Questions

Where does Codex keep token usage on my computer?

In its session logs at ~/.codex/sessions/**/*.jsonl. token_count events carry the usage for each turn, and the model comes from turn_context.

Does Caldera need my OpenAI account or an API key?

No. The Caldera plugin reads the Codex logs on the computer where you run Obsidian and totals only usage fields: model, token counts and timestamps.

Does Caldera show what Codex costs me?

No. Only token counts and model names are published. Money amounts are left out on purpose.

Can I combine Codex with Claude Code and other computers?

Yes. The plugin reads Claude Code and Codex logs on the same computer by itself. For other computers or your own products' API usage, have your AI agent write an ai block with counts by model and provider into Caldera/activity.json.

Is it free?

Yes. The plugin, your page and the AI usage section are free and open source.
